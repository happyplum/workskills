# 名词表（glossary）

> 术语唯一权威表：正文以简称使用这些词，定义以本表为准；正文与本表冲突时以本表为准并回改正文。
> 结构层名词管「放哪」，代码内部层名词管「怎么写」。

## 结构层

| 名词 | 定义 | 判定 / 例子 | 常见误读 |
|---|---|---|---|
| 落位（placement） | 决定「这个文件放哪个目录」的动作总称 | 先分类后落位（H5），不按「离调用近」 | ≠「放置文件」的机械动作 |
| 主分界规则 | 业务事实按「种类」集中；页面 UI 按「业务」共置 | 口诀：**删掉这层 UI 它还成立吗？** 成立→种类集中；跟着页面生死→共置 | 不是「全都共置」也不是「全都集中」 |
| 种类集中 | 按技术种类归堆：API 声明与类型、全局/会话状态、文案(i18n)、无状态工具、全局样式入口 | apis/ types/ stores/ locales/ utils/ styles/ | ≠ 按层横切（不按 controller/service 分层） |
| 共置（colocation） | 页面私有物（组件/子视图/静态资源/私有类型）与页面同目录 | workflow 页的编辑器工具条放 workflow/ 内 | ≠ 所有东西都跟页面走（事实仍集中） |
| 门口 / 窄门口（doorway） | UI 单元（页面、feature 目录、组件目录）的**唯一公开入口文件**（惯例 index.ts）；消费者只经门口导入 | 「窄」= 只 re-export 公开面、不含逻辑 | 误读一：所有目录都要 barrel——**选择性**：种类集中区（apis/stores/types/locales/utils/styles 全类）不设 |
| fat barrel（反模式） | 门口膨胀：几十行导出、多层转发、藏 owner、含运行逻辑 | — | 门口 ≠ 导出一切 |
| 分册（booklet） | 按业务域各维护一册路由/身份表（settings 一册、chat 一册） | 宿主装配 = 各宿主 import 分册后自行决定挂载、启用、接 history、本地 overlay | 误读：共享分册包含某宿主私有路由——禁止 |
| 三区 | 公共组件三个区：**通用能力区**（零业务语义、可拷任意项目）/ **业务复用区**（带产品语义、跨页/跨宿主复用）/ **widget 特区**（仪表盘挂件） | 对应落位：@tnyma/ui 型 / packages/console 型 / Workbench 型 | 不是两个区（通用 vs 公共），是三个 |
| 能力件 | 剥掉业务文案与接口后仍成立的可移植组件 | 富文本、日期选择、通用下拉 | ≠ 「看起来通用的组件」 |
| 业务件 | 绑产品语义的组件：本域字段、筛选条件、业务状态机 | 带筛选的业务列表 | |
| 能力/业务判定口诀 | **去掉这个域的文案和接口，它还成立吗？** | 成立→能力件；不成立→业务件 | |
| 抽取时机 | 第二调用方**出现**才抽业务复用区；能力件即使当前单页使用也要单独判一次 | 列表先留页内；富文本单页用也要判可移植性 | 误读一：「以后可能复用」就提前抽；误读二：明显能力件因「只有一页用」永久私有化 |
| 同构（isomorphism） | 同类页面/模块内部组织一致：同为设置分区应有相同内部结构 | 两个 settings section 打开后文件形态相同 | ≠ 目录长相完全一样（不抹平真实边界） |
| 人可定位 | 关键业务路径在 IDE 目录树中**逐层可翻到**，不依赖全文搜索 | AI 能搜到 ≠ 人可定位 | |
| 命名前缀信号 | 通用能力件可用产品前缀标记（如 DM）；**业务件永不带** | 前缀=能力件信号，不是装饰 | |

## 代码内部层

| 名词 | 定义 | 例子 / 要点 | 常见误读 |
|---|---|---|---|
| 薄封装 + 位置路由 | 封装只标准化「**声明**」（列配置、slot 位置、类型目录），不吞并「**职责**」（loading/空态/分页数据归页面） | 位置路由 = 按名（slot:{name}）把自定义内容路由到声明位置 | ≠ 封装越少越好；是「声明集中、职责归页面」 |
| 双信封桥 | 同一拦截层兼容 mock 信封与真实后端信封（以**缺省字段直通**区分），mock 与真实零成本切换 | retCode 缺省→直通（mock 路径） | ≠ 两套请求代码 |
| 错误三级回退 | 码表(值为 i18n key) → 原始 msg → 兜底文案 | 占位符（{count}）由响应 data 填充 | |
| 机制先行、数据后置 | 先建机制骨架（空枚举 + 完整分支、占位组件），运行时决策数据后填 | LOGOUT_CODES=[] + 完整登出分支 | ≠ 留半成品；机制是完整的，数据位是空的 |
| 列表页五件套 | ①查询分页态页内持有 ②query() 先回页 1 ③统一 changePage(num,size) ④try/finally 管 loading ⑤重置=逐字段+页1+重查 | 五件齐 = 同构列表页 | 少任何一件即漂移 |
| 一表单多模式 | 新增/编辑/详情**共用一个表单组件**，路由参数分模式；模式判定入口必须统一 | 同一文件三种形态 | ≠ 一个组件堆三种 if 散落各处 |
| 字段级禁用矩阵 | `:disabled="isDetail || 业务态"`——禁用在字段级、可叠加业务条件 | 详情态+离职态同时禁用某字段 | 表单级 disabled 覆盖不了业务叠加 |
| Dialog 状态机 | visible+type 两轴；destroy-on-close 杀 DOM 与校验态，**数据模型手工重置**；before-close 统一 X/遮罩/取消的草稿清理 | 编辑只拷贝字段防 row 污染 | 误读：destroy-on-close 会重置一切——响应式模型它杀不掉 |
| 状态准入 | 只有**跨页导航/会话态**（用户/菜单/历史）进全局 store；表单/筛选/弹窗态留页内 | | 误读：状态多一点就进全局 |
| 宁重查不脏缓存 | 页面列表数据不缓存（含 keep-alive 式页面缓存），切回即重查 | 假 tab 记录路径不缓存页面态 | |
| 焦土式登出 | 登出清**整个**会话存储而非逐键清——新增缓存键自动被覆盖，免维护清理清单 | sessionStorage.clear() | |
| 三通道通信 | props 下发 + 事件上抛 + ref 实例方法，之外不新增通道 | Vue：零 provide/inject、零事件总线；React：不用 Context 传业务数据流 | Context/组件库注入可以放「真正全局不变项」 |
| 边界归一化一次 | 外部 DTO 只在进入内部模型的边界归一化一次，内部不再二次映射 | 日期区间→ISO 在组装请求参数时做 | |
| 负面清单 | 用「不做什么」定义架构（不做 X 缓存/不用 X 通道/不传 X 参数），比正面穷举稳定 | 本表所在 skill 大量使用 | |
| 元习惯 | 「为什么这么想」层的思维定式（八条），比具体规则更稳定 | 模板即法典 / 人可定位优先 | |
