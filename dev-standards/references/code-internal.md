# 代码内部层：怎么写（框架中立）

## 请求与错误管道

- **单一请求门**：所有 HTTP 经一个包装层；业务码判定、会话过期判定只在这一层，调用点不重复判。
- **双信封桥**：mock 信封与真实后端信封可在同一拦截层共存（用「缺省字段直通」区分），mock 与真实后端无成本切换。
- **错误码三级回退**：码表（值为 i18n 键名）→ 契约明确可面向用户且不含敏感信息的原始消息 → 兜底文案；不符合展示条件的原始消息跳过。占位符（`{count}` 等）由响应 data 填充（如剩余次数、锁定分钟数）。
- **机制先行**：登出码表等运行时决策数据留空位（空数组 + 完整分支），决策后只填数据不改机制。
- **HTTP 层错误统一一个码**，与业务错误分叉。
- **惰性依赖**：拦截器内延迟获取状态 store，规避初始化顺序与循环依赖。

## 错误反馈与布局稳定

这是个人交互规范，适用于 React、Vue 等前端栈，不是框架自动保证的行为。目标是**让用户知道发生了什么，同时保留页面结构、仍有效的内容和可继续操作的上下文**；不是要求故障组件继续渲染，也不是等待整页请求完成后再提示。

### 七条约束

1. **提示与主体分离**：普通成功、警告、请求或操作失败，不得通过顶层提前返回、条件分支、`return null` 等替换或隐藏页面主体；同样不得把表格、卡片、表单整个替换成一行错误文字，或往布局任意插入错误块撑开网格。保留导航、标题、工具栏、外层容器和不依赖失败数据的区域；加载与失败仅影响实际依赖区域。通知本身不得导致组件换 `key`、类型或位置而重建、丢失输入。真实渲染崩溃与访问限制按下述例外处理。
2. **按语义选择反馈位置**：按下表选择消息层、字段反馈、持续状态或对话框；不把所有失败都做成 Toast，也不把提示一律塞进正文。持续故障可使用组件已有或本次明确设计的状态区域，不得把「局部降级」理解为允许拆掉整个卡片。普通消息不抢焦点；复用公共组件的状态播报、字段关联与对话框焦点管理能力。
3. **保留有效状态，不伪造结果**：当前已挂载视图在同一资源、查询条件及身份下刷新失败，且旧数据仍允许使用时，保留原内容并明确刷新失败；不新增跨页缓存，不把前一个筛选、实体或租户的数据当成当前结果。提交失败保留草稿和弹窗，停止本次提交的 loading，不执行成功后的关闭、清空或跳转。加载失败、成功空结果、尚未加载必须区分；不得用空数组、默认值或假数据把失败改成成功。
4. **副作用与通知归属明确**：Toast、MessageBox 等在事件、请求完成回调或必要的 Effect 等渲染外路径触发，不在 React 组件函数主体、JSX、`useMemo` 或 Vue 模板、computed 求值中调用。一次失败由一个明确的处理层负责通知，避免请求拦截层、查询订阅者与页面重复弹出；重渲染、Effect 重跑和自动重试不能重复通知同一次失败。字段反馈已足够时不再附加 Toast；持续状态加一次必要通知可以共存。用户主动重试后再次失败仍应得到有效反馈，不以永久去重掩盖新失败。不通过定时器或等待全部请求人为实现「先渲染完再提示」。
5. **保留失败语义，限制传播范围**：按现有请求契约保留 throw/reject 或显式错误结果，不空 catch、不返回成功数据压住错误。核对路由 loader/action、查询库、Suspense 与错误边界如何传播和替换 UI，不把可局部处理的失败送到整页兜底。React 的子组件渲染错误不能靠包住 JSX 的 try/catch 捕获；优先复用既有 Error Boundary，把可独立恢复的区域包在稳定外壳内，根边界作为最后兜底，不为每个小组件新增边界。Vue 捕获错误后也不能持续重渲染同一故障内容。故障子树允许替换为恢复界面，不承诺保留该子树内部状态；不能靠删除边界、关闭开发错误遮罩或全局吞异常来宣称修复。
6. **复用公共反馈能力与布局约束**：使用项目已有消息 API、挂载容器、表单校验和加载/失败状态能力，保证需要报告局部失败的消息宿主不随该故障区域一起卸载。遵循公共组件与响应式布局的尺寸、间距和溢出规则，避免容器因只剩短错误文本而坍塌；不要求成功态与失败态像素高度完全相等，不用任意固定高度、裁剪或绝对定位补丁掩盖主体布局问题。公共能力不足时在正确 owner 补齐，不在业务页另造 Toast、平行错误组件或覆写组件内部样式。正文和通知只显示可面向用户的消息，不输出堆栈、原始响应或机密；诊断走项目已有且脱敏的日志渠道。
7. **例外有依据，改动有边界**：无权限、资源不存在、身份失效以及页面确实无法安全继续时，遵循项目已有访问控制与专用页面；不为保留界面继续展示越权或失效内容。仅影响局部资源的限制不得无依据升级成整页阻断。修复前指出实际替换布局的分支、通知归属和影响区域；仅修改本次涉及路径，不建立新通知框架、不为这些规则强加依赖、重试、缓存或全仓重构。下列框架说明仅用于已采用对应技术的项目，不构成引入技术的要求。

### 反馈选择

| 场景 | 默认反馈与保留范围 |
|---|---|
| 需要反馈且无字段级或既有专用反馈承载的普通操作结果 | 项目 Toast / Message；保持主体，不因一次提示加横幅或替换内容；主动取消或已失效请求的正常取消不冒充失败，超时仍按失败处理 |
| 首次加载失败，无可用数据 | 保留外层布局与可用控件，在原数据容器的状态区域显示简短失败及适用的恢复入口；不能只留一个消失的 Toast、永久骨架屏或「暂无数据」 |
| 已有适用数据，刷新失败 | 保留可用内容，明确刷新失败；持续影响使用时由既有状态区域承载，不反复弹消息或覆盖内容 |
| 字段校验失败 | 错误与对应字段关联，保留输入；需要汇总时用既有表单错误摘要，不强制附加 Toast |
| 持续离线、部分功能不可用 | 既有或明确设计的状态槽、Alert / Notification 等持续反馈；不临时往任意布局位置插入提示，不仅依赖会自动消失的消息 |
| 确实需要用户确认、选择或处理后继续 | 项目 MessageBox / Dialog；保持底层页面，按组件约定管理焦点，普通失败不默认升级成模态阻断 |
| 渲染崩溃 / 访问限制 | 分别按故障边界或既有访问规则降级；保留安全且正常的外层区域，恢复操作必须实际能重试或离开 |

### 框架落地易错点

- **React**：提前返回不是原罪；问题是普通错误分支越过了应保留的布局与状态边界。状态槽内的错误展示是合法的，不得用 grep 命中 `if (error)` 就机械删除。组件函数写法约束针对业务组件；必要的底层错误边界遵循框架 API，优先复用已有实现，不为避免类式边界而吞掉渲染错误。
- **路由与查询库**：核对项目实际版本。React Router 的路由错误可能切换到最近的边界；TanStack Query 的 query function 依赖 throw/reject 标识失败，而是否抛给渲染边界是另一个环节。v5 的 `useSuspenseQuery` 不能任意配置 `throwOnError`，不能统一要求设为 `false`；按已用模式选择局部边界及恢复接线。使用 Suspense 时也保留外层结构，不为一个区域的加载回退替换整页。
- **Vue**：`errorCaptured` / `onErrorCaptured` 捕获不等于出错组件一定渲染成功；不得把「像 Vue 一样」解释成捕获后无条件继续渲染。

### 本次涉及界面的验收锚

按改动实际涉及的场景做短程验证，不要求无关页面或纯文档变更运行产品全套测试：

- 首载失败、加载到失败：原页面/卡片容器、标题和工具栏仍在，无异常坍塌、撑开、遮挡或溢出；数据区明确失败，其他区域可用。
- 刷新失败：适用内容保持；切换筛选、实体或身份后不冒用旧数据；成功空结果与失败不同。
- 提交失败：输入、弹窗及正常区域保留；loading 结束，没有成功提示、清空或跳转；字段反馈不重复弹 Toast。
- 重渲染、共享请求订阅或自动重试：同一次失败不反复通知；主动重试的新失败可被感知；取消不误报。
- 局部渲染异常与恢复：受影响子树降级，正常外壳保留；恢复入口真实生效，成功后移除过期错误状态。
- 视觉和交互变化：核对受影响区域在项目支持的主题、尺寸和长文案下的布局，以及消息播报、字段关联、对话框焦点；不能用单元测试通过代替必要的浏览器检查。

### 技术依据与适用边界

以下官方文档支撑运行机制和组件语义；上述默认反馈策略是个人规范。具体 API 以项目安装版本为准。

- React：[错误边界及捕获范围](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary)、[渲染纯净性](https://react.dev/reference/rules/components-and-hooks-must-be-pure)、[组件替换与状态重置](https://react.dev/learn/preserving-and-resetting-state)、[Suspense 回退范围](https://react.dev/reference/react/Suspense)。
- [React Router 错误边界](https://reactrouter.com/how-to/error-boundary)、TanStack Query：[查询失败语义](https://tanstack.com/query/latest/docs/framework/react/guides/query-functions)、[Suspense 与 throwOnError](https://tanstack.com/query/latest/docs/framework/react/guides/suspense)。
- [Vue errorCaptured](https://vuejs.org/api/options-lifecycle.html#errorcaptured)：错误捕获不保证原内容可继续渲染。
- Ant Design：[Message](https://ant.design/components/message/)、[Alert](https://ant.design/components/alert/)、[Modal](https://ant.design/components/modal/)；仅用作轻量反馈、持续提示、模态交互的语义参照，不指定 UI 库。
- W3C WCAG 2.2：[状态消息](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)、[错误识别](https://www.w3.org/WAI/WCAG22/Understanding/error-identification)。

## 表格/列表协议（配置驱动）

- **声明式列**：columns 配置数组 + 自定义单元格按名路由（slot/render 位置在配置里声明，封装层零改动支持扩展）。
- **薄封装不吞职责**：表格封装不拥有 loading/空态/分页数据，页面注入；分页尺寸与页码事件合流为单一 `change(page, size)`。
- **列配置持久化**：按表 id 记忆列可见性与顺序；列标识 prop 缺失时用 label 兜底。
- **透传代理**：封装组件把底层实例方法透出（透明 expose / forwardRef），不逐个重声明 API；刻意只透必要的。
- **列表页五件套同构**：
  1. 查询态 + 分页态由页面持有（不进全局 store）
  2. `query()` 先把页码重置为 1（筛选即回首页）
  3. 统一的 changePage 处理函数
  4. try/finally 管 loading
  5. 重置 = 逐字段还原 + 回页 1 + 重新查询
- **边界归一化一次**：如日期区间 → ISO 字符串，在组装请求参数时做，不在展示层反复转。

## 表单协议

- **一表单多模式**：新增/编辑/详情共用一个表单组件，路由分模式；模式判定入口必须统一（历史漂移教训：多种判定写法并存，收敛为唯一入口是必做改造）。
- **字段级禁用矩阵**：`:disabled="isDetail || <业务态>"` —— 字段级允许业务态叠加；表单级 disable 表达不了这种矩阵。
- **校验规则就地内联**：跨字段校验需要闭包引用同表单字段，抽出去就得传参；多卡片表单共享一个数据模型、按卡分组规则；触发时机 blur（输入）/change（选择）。
- **Dialog 状态机**：visible + type 两态；`destroy-on-close` 杀 DOM 与校验态，**响应式数据模型手工重置**（它不会跟着死）；编辑时只拷贝字段防原对象污染；X / 遮罩 / 取消统一走 before-close 清理草稿。
- **提交成功 → 关闭 + 列表回第 1 页刷新**（「新增后让你看见它」）。
- **提交 loading 必须有**（try/finally）——历史实现缺口，新代码必补。

## 状态与缓存观

- **全局态准入** = 跨页导航/会话态（用户/菜单/历史）。表单、筛选、弹窗态留页内。
- **宁重查不脏缓存**：不缓存页面级列表数据；tab 化导航记录路径而非页面状态，切回必然新数据。
- **会话存储与标签页同生共死**（sessionStorage 语义）；登出焦土式清空（整仓 clear 而非逐键清，未来新增缓存自动被覆盖，免维护清单）。
- **多租户职责切分**：身份租户进凭证（token 承载），数据范围进查询参数（页面自己声明），不做全局注入。

## 通信纪律

- **通道收窄**：组件通信 = props 下发 + 事件上抛 + ref 实例方法，三件套之外不新增通道。Vue 侧零 provide/inject、零事件总线；React 侧不用 Context 传业务数据流。
- **受控代理手写**（v-model 多绑定 / 受控 + onChange），不用魔法双向宏。
- **loading 类布尔命名全局统一**（如 tableLoading）。
- **封装组件暴露最小 API**（`open()` / `resize()` 级别），内部状态私有。

## 负面清单（用「不做什么」定义架构）

- 不做页面级缓存（keep-alive 类）
- 业务组件不用 options/类式写法（Vue：组合式；React：函数组件）；底层错误边界按框架 API 与上述反馈规则处理
- 不用 query 传实体身份（path 参数）
- 不提交 lock 文件 / .vscode / dist
- 兼容层、双写、旧字段 fallback 默认禁止——迁移完成后删旧实现
- 不建业务 service 中间层（API 薄包装直连）

## 工具链口味

- **提交**：`[type]` 前缀 + 自定义解析器；分支 `<type>/<基线>-<缩写>-<描述>`；同主题 >5 commit squash。
- **Lint**：快扫器先行 → ESLint 兜底；风格只归格式器管。
- **构建注入 git 信息**（commit/branch/时间）+ 控制台可调展示函数——生产排查最低成本方案。
- **代理即路径约定**：后端路径 = 前端路径，按服务前缀分流，零 rewrite。
- **组件库按需三层**：模板解析器自动 + 脚本手动 import + 样式按需；注意手写引入的组件需手动补样式（已知坑）。
- **运行时主题派生**：主色经算法派生梯度（light-N/dark-N）写 CSS 变量，不做色板硬拷贝。
