# 代码内部层：怎么写（框架中立）

## 请求与错误管道

- **单一请求门**：所有 HTTP 经一个包装层；业务码判定、会话过期判定只在这一层，调用点不重复判。
- **双信封桥**：mock 信封与真实后端信封可在同一拦截层共存（用「缺省字段直通」区分），mock 与真实后端无成本切换。
- **错误码三级回退**：码表（值为 i18n 键名）→ 原始消息 → 兜底文案。占位符（`{count}` 等）由响应 data 填充（如剩余次数、锁定分钟数）。
- **机制先行**：登出码表等运行时决策数据留空位（空数组 + 完整分支），决策后只填数据不改机制。
- **HTTP 层错误统一一个码**，与业务错误分叉。
- **惰性依赖**：拦截器内延迟获取状态 store，规避初始化顺序与循环依赖。

## 表格/列表协议（配置驱动）

- **声明式列**：columns 配置数组 + 自定义单元格按名路由（slot/render 位置在配置里声明，封装层零改动支持扩展）。
- **薄封装不吞职责**：表格封装不拥有 loading/空态/分页数据，页面注入；分页尺寸与页码事件合流为单一 `change(page, size)`。
- **列配置持久化**：按表 id 记忆列可见性与顺序；列标识 prop 缺失时用 label 兜底。
- **透传代理**：封装组件把底层实例方法透出（透明 expose / forwardRef），不逐个重声明 API；刻意只透必要的。
- **列表页五件套同构**：
  1. 查询态 + 分页态由页面持有（不进全局 store）
  2. `query()` 先把页码重置为 1（筛选即回首页）
  3. 统一的 changePage 处理函数
  4. try/finally 管 loading
  5. 重置 = 逐字段还原 + 回页 1 + 重新查询
- **边界归一化一次**：如日期区间 → ISO 字符串，在组装请求参数时做，不在展示层反复转。

## 表单协议

- **一表单多模式**：新增/编辑/详情共用一个表单组件，路由分模式；模式判定入口必须统一（历史漂移教训：多种判定写法并存，收敛为唯一入口是必做改造）。
- **字段级禁用矩阵**：`:disabled="isDetail || <业务态>"` —— 字段级允许业务态叠加；表单级 disable 表达不了这种矩阵。
- **校验规则就地内联**：跨字段校验需要闭包引用同表单字段，抽出去就得传参；多卡片表单共享一个数据模型、按卡分组规则；触发时机 blur（输入）/change（选择）。
- **Dialog 状态机**：visible + type 两态；`destroy-on-close` 杀 DOM 与校验态，**响应式数据模型手工重置**（它不会跟着死）；编辑时只拷贝字段防原对象污染；X / 遮罩 / 取消统一走 before-close 清理草稿。
- **提交成功 → 关闭 + 列表回第 1 页刷新**（「新增后让你看见它」）。
- **提交 loading 必须有**（try/finally）——历史实现缺口，新代码必补。

## 状态与缓存观

- **全局态准入** = 跨页导航/会话态（用户/菜单/历史）。表单、筛选、弹窗态留页内。
- **宁重查不脏缓存**：不缓存页面级列表数据；tab 化导航记录路径而非页面状态，切回必然新数据。
- **会话存储与标签页同生共死**（sessionStorage 语义）；登出焦土式清空（整仓 clear 而非逐键清，未来新增缓存自动被覆盖，免维护清单）。
- **多租户职责切分**：身份租户进凭证（token 承载），数据范围进查询参数（页面自己声明），不做全局注入。

## 通信纪律

- **通道收窄**：组件通信 = props 下发 + 事件上抛 + ref 实例方法，三件套之外不新增通道。Vue 侧零 provide/inject、零事件总线；React 侧不用 Context 传业务数据流。
- **受控代理手写**（v-model 多绑定 / 受控 + onChange），不用魔法双向宏。
- **loading 类布尔命名全局统一**（如 tableLoading）。
- **封装组件暴露最小 API**（`open()` / `resize()` 级别），内部状态私有。

## 负面清单（用「不做什么」定义架构）

- 不做页面级缓存（keep-alive 类）
- 不用 options/类式组件写法（Vue：组合式唯一；React：函数组件唯一）
- 不用 query 传实体身份（path 参数）
- 不提交 lock 文件 / .vscode / dist
- 兼容层、双写、旧字段 fallback 默认禁止——迁移完成后删旧实现
- 不建业务 service 中间层（API 薄包装直连）

## 工具链口味

- **提交**：`[type]` 前缀 + 自定义解析器；分支 `<type>/<基线>-<缩写>-<描述>`；同主题 >5 commit squash。
- **Lint**：快扫器先行 → ESLint 兜底；风格只归格式器管。
- **构建注入 git 信息**（commit/branch/时间）+ 控制台可调展示函数——生产排查最低成本方案。
- **代理即路径约定**：后端路径 = 前端路径，按服务前缀分流，零 rewrite。
- **组件库按需三层**：模板解析器自动 + 脚本手动 import + 样式按需；注意手写引入的组件需手动补样式（已知坑）。
- **运行时主题派生**：主色经算法派生梯度（light-N/dark-N）写 CSS 变量，不做色板硬拷贝。
