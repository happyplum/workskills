# lzy 通用开发规范（框架中立版）

## 这是什么

对 lzy 开发习惯的三层蒸馏：**原则层**（元习惯，为什么这么想）→ **落位层**（东西放哪）→ **代码内部层**（怎么写）。证据源：vue-cli（旧代模板）→ vue-vite-cli（新代法典）→ group-web（生产实态），并经架构裁决收敛。适用于任何前端栈；Vue 专属细节见姊妹 skill `vue-standards`（自包含，无需先读本 skill）。

## 八条元习惯（原则层）

| # | 习惯 | 一句话 | 反面 |
|---|---|---|---|
| 1 | 模板即法典 | 经验固化成可克隆起点（模板 + 规则文档），新项目从法的版本开始 | 每个项目从零手配 |
| 2 | 生产是权威源 | 模板是投影，定期从生产反向萃取（「同步 XX 组件」式提交） | 模板先行、生产漂移 |
| 3 | 机制先行、数据后置 | 先搭骨架留空位（空枚举 + 完整分支、占位组件），运行时决策后填 | 等数据齐了才写机制 |
| 4 | 薄封装 + 位置路由 | 封装标准化「声明」（列配置、slot 位置、类型目录），不吞并「职责」（loading/分页留给页面） | 大而全的超级组件 |
| 5 | 用「不做什么」定义架构 | 负面清单比正面清单稳定：不做 X 缓存、不用 X 通道、不传 X 参数 | 靠正面穷举防漂移 |
| 6 | DEV/生产双轨洁癖 | demo 页、dev 路由菜单全部环境标志圈禁；生产表出厂即空 | demo 混进生产构建 |
| 7 | AI 是一等协作者 | WHY 留痕（决策文档、坑的根因记录），为 AI 结对维护档案 | 只有人能读懂的隐式上下文 |
| 8 | 人可定位优先 | 一切结构为「IDE 里的自己」能顺着翻到而设计；AI 搜索只是加速器 | 用「AI 能搜到」当结构合格 |

## 主分界规则（最重要的一条）

> **业务事实按「种类」集中；页面 UI 按「业务」共置。**

- 按种类集中：API 声明与类型、全局/会话状态、文案（i18n）、无状态工具、全局样式入口。
- 按业务共置：页面文件、页面私有组件、私有子视图、私有静态资源，进同一个业务文件夹。

判断口诀：**删掉这层 UI 它还成立吗？** 成立 → 种类集中；跟着页面生死 → 共置。

## 深核速览（换框架也不变的 10 条）

1. 每个 UI 单元一个窄门口（index 入口文件）
2. 通用件与业务件物理分区，命名前缀可作信号
3. 表格列配置声明式 + 自定义单元格位置路由
4. API 薄包装、类型随行（每端点一函数，无中间 service 层）
5. 组件通信只有三通道：props 下发、事件上抛、ref 实例方法
6. 不缓存页面列表数据（宁重查不脏缓存）
7. 组件写法唯一（Vue：script-setup 组合式；React：函数组件）+ 组件名必填 + 模板/JSX 标签 PascalCase
8. UI 库就地覆写层（不 fork 组件库）
9. 错误码查表 + 会话过期拦截位常备
10. 提交卫生：[type] 格式、锁文件/编辑器配置/产物不入库

## 框架映射提示（Vue 概念 → React 等价）

| Vue 侧习惯 | React 侧等价 |
|---|---|
| feature 目录 index.ts 门口 | 目录 barrel / 包 public API（同样选择性设置） |
| 零 provide/inject | 不用 Context 传业务数据流（Context 只放真正全局不变项） |
| 手写 v-model 代理（computed get/set） | 受控 props + onChange，同样避免魔法双向 |
| slot 位置路由（slot:{name}） | children / render props 按名路由 |
| defineOptions(name) 必填 | 组件 displayName / 文件即组件名 |
| 透明 expose（vm.exposed） | forwardRef 直透底层实例 |

映射只是等价关系，不是逐条强制；落位层与代码内部层的**原则**在两个栈下同样成立。

## 边界声明

本 skill 是个人规范的主版本；具体项目落地时以项目规则（AGENTS.md）为本地版本，冲突以项目特有边界（宿主/包所有权/身份单源）优先。协同开发或非本人主导的项目中，仅在用户明确要求时应用本 skill，不主动施加或改造项目结构。见 `references/localize.md`。
