# 完成工作审查

## 概述

根据改动风险动态选择**最少但充分**的审查维度，不固定启动一堆审查代理，也不把高成本的深度推理专家当成普通代码审查员。先复用实现阶段已有的新鲜验证证据，只补充真正可能改变结论的检查。

> **与 `audit-loop` 的分工**：本 skill 解决「本次改动该查哪些维度、用多重的验证强度」；如果查出问题后需要进入「修复 → 同一审查会话增量复审 → 直到零问题 PASS」的多轮收敛，可配合 `audit-loop` 使用。

## 审查前固定输入

开始审查前，先整理好最小必要输入：
- 用户目标与硬约束；
- 代码基线与待审改动（commit / branch / 变更文件列表 / diff）；
- 实现阶段已经跑过的定向测试、类型检查或运行结果；
- 运行入口与已知未决项。

如果缺少会影响审查结论的关键信息，先补齐再审；不要把整个仓库或整段长对话一股脑倾倒给每个审查任务。

## 审查维度按需选择

按改动实际触及的风险面启用对应维度，未命中的维度不启动，并在结论里记录 `SKIPPED: <原因>`（`SKIPPED` 不代表缺陷）。普通小改动绝不为了「看起来全面」强行拉满全部维度。

| 审查维度 | 何时启用 | 推荐执行方式 |
|---|---|---|
| 目标与约束核对 | 改动范围较大、需求有多条，或中途发生过范围变更 | 轻量或标准审查；局部小改动由当前会话直接核对即可 |
| 实测 QA | 业务行为、CLI、API、UI 或构建产物有实际变化 | 实际运行最小充分的验证场景，不只看代码猜行为 |
| 代码质量 | 非机械改动、触及公共调用链或跨模块变更 | 标准代码审查，结合 diff 与相邻已有实现模式对照 |
| 安全检查 | 触及鉴权/权限、外部输入边界、密钥/凭证、文件/网络操作或依赖变更 | 针对安全边界做专项核对；深度安全审计交专用安全流程 |
| 上下文与历史核查 | 需求来源、模块归属、关联 issue/PR 或既有设计约束存在歧义 | 定向查证相关文档、提交历史或关联记录，只解决未决疑问 |
| 架构与高风险裁决 | 收集完证据后，仍存在未决的架构设计、并发、数据迁移或高风险结构决策 | 仅针对单一未决难题调用高推理能力专家，不用于常规审查 |

## 调度与成本控制

- **低成本优先**：能用常规检查或标准审查解决的问题，不直接上最贵的高推理模型/专家。升级高档分析时必须说清低一档缺失的能力——「diff 大」「测试多」或「想更稳妥」不构成升级理由。
- **最小上下文投喂**：每个审查维度只拿共享基线 + 本维度需要的证据摘要，不重复投喂无关文件。
- **独立并行，有依赖则串行**：彼此独立、不争抢同一运行资源（如同一端口或同一构建目录）的审查维度可以同轮并发推进；存在先后依赖或共享运行时资源的必须串行。
- **叶子职责单一**：单个审查子任务不再继续向下派生子审查；同一验证目标只安排一个负责人，避免重复跑同一套测试。

## 验证强度阶梯

从成本最低、且能最快证伪目标行为的项目原生检查开始，逐级按需升级：

1. **局部改动**：跑受影响模块的定向单元测试 / 场景验证；
2. **包内共享逻辑变更**：补跑对应包范围的类型检查与相关测试；
3. **公共接口/跨包契约变更**：补跑关联集成检查；
4. **全量门禁（full verify / build / 浏览器全矩阵）**：仅当小检查失败、影响范围无法界定、临近发布或用户明确要求时才启用。

同一代码 revision 下刚刚跑过、且未再改代码的验证证据直接复用，不重复浪费时间。

## 结论聚合与报告

每个已启用的维度返回三态之一，并附待审 revision、具体证据和阻断问题：
- `PASS`：核查通过，无阻断问题；
- `FAIL`：存在必须修复的阻断问题；
- `INCONCLUSIVE`：证据不足或环境受阻，无法下定论。

**总体聚合规则**：
- 任一必需维度为 `FAIL` → 总体 `FAIL`；
- 无 `FAIL` 但存在必需维度为 `INCONCLUSIVE` → 总体 `INCONCLUSIVE`；
- 全部必需维度为 `PASS` → 总体 `PASS`。

最终向用户汇报时，对问题做去重，**只保留阻断项和最高价值的改进建议**，不要把一堆吹毛求疵的风格微调抛给用户。

## 反例

| 看似合理但错误 | 正确做法 |
|---|---|
| 无论改动大小，每次都固定拉满 5 个审查子代理和多个高价架构专家 | 按改动实际风险只启用最少充分的维度，其余标 `SKIPPED` |
| 把普通代码可读性或常规 QA 交给高成本架构专家 | 常规检查走标准审查 + 实际运行验证，高推理专家只裁决未决结构难题 |
| 彼此独立的维度一个接一个串行空等 | 独立且资源隔离的检查同轮并发，有依赖或抢资源的串行 |
| 给每个审查任务塞进全仓文件和整段历史对话 | 仅提供共享基线 + 该维度必需的局部证据 |
| 改了几行局部逻辑却每次重跑全量 build 和端到端测试矩阵 | 定向检查先行，复用同版本新鲜证据，有充分理由再升级 |
| 顺手审查与本次改动无关的陈年旧代码并列成阻断项 | 只聚焦本次目标、约束与真实可达的影响范围 |
